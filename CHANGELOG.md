acting on a request that sounds like something already handled.

## 2026-10-31 - accessibility-auditor gate: brand-forward redesign
- **[DONE] Verdict: ACCESSIBLE WITH NOTES** (no blockers; local only, NOT deployed). Audited index.html via local static server + Playwright headless (mock keychain) at 1280/768/375/320, 640x400 (200% zoom), 320x256 (400%), reduced-motion, forced-colors, dark scheme. Pass: body/lede/chip/footer text >= 4.5:1 over real rendered pixels incl. speed-line streaks (text hidden, background sampled per line box; remaining sub-4.5 hits were measurement artifacts from the ink slab, text-stroke and header-offset); focus ring is 3px ink (>= 3:1 on lime and cream); no 2D scroll at 320/400%/200% (chip row scrolls on its own, nav scrollWidth 688 vs 248-324 client); no target < 44px after fix; one h1; decorative icons/streaks/orbit aria-hidden; logo alt "Garoo Interactive", object-fit contain, original files; reduced-motion leaves only 0.001ms once-through entrance animations; nothing flashes; orbit bob stops after 5 cycles (~23s).
- **Fixes applied in index.html (CSS/JS/ARIA only):** (1) nav `scroll-padding-inline` + small `focusin` handler so a focused chip scrolls fully clear of the right-edge fade (before: Starcarver/Arcade chips stayed half-hidden under the fade when focused by keyboard); (2) `.logo` link <=860px gets 6px side padding (was 32px wide, now 44x46); (3) `nav a.is-active` gets an underline so the current section is not shown by colour alone (lime vs cream ~1.4:1; aria-current was already set); (4) `<main tabindex="-1">` + `main:focus{outline:none}` so the skip link moves focus, not just scroll; (5) `@media (forced-colors: active)` hides the decorative streak SVGs.
- **Notes (non-blocking):** (a) chip row has no explicit scroll affordance beyond the fade and the half-visible next chip; acceptable, and every nav target is also reachable in page flow (band chips, "How we work", footer links); (b) pre-existing infinite loops: `.launch-badge::before` pulse and `.phone-bezel` float are reduced-motion-safe but not user-pausable (WCAG 2.2.2) unless the 20s stop at ~line 564 covers them; (c) page is light-only (no dark scheme, no `color-scheme` meta); lime band/cream plate stay as designed, forced-colors renders legibly; (d) aria-current is "true", "location" would be more precise; (e) text-stroke headings were not pixel-measured (stroke is ink on light surfaces, visually fine). Not verified: real screen readers (VoiceOver/NVDA), real devices, real Windows High Contrast, Safari focus-scroll behaviour.
